# 多 Agent 协作说明

主对话是 orchestrator，负责理解用户目标、选择合适 agent、合并结果并做最终交付。

## 协作模式

1. **单 agent**：任务边界清晰时，按路由表交给一个 agent 或由主对话等价执行。
2. **顺序协作**：存在前后依赖时，先设计/规格，再实现，再测试。
3. **并行协作**：美术、UI、测试、后端等可拆分任务可以并行，但共享契约必须先明确。
4. **骨架先行**：多个模块会互相引用时，先由主对话或 lead agent 定义公共契约，再分工实现。
5. **交回 main**：跨职能决策、白名单外 skill、工具权限不足、用户意图不清、三轮收敛失败时，立即交回主对话。

## 程序框架立场

本模板不预置运行时代码框架。任何模块系统、事件系统、输入系统、配置表、资源加载、服务端协议都由具体项目按需求选择。

Agent 不应假设项目存在 `GameApp`、`ModuleRunner`、`EventBus`、`InputModule`、`DataTableGenerator` 或 `Assets/Scripts/Core`。
