# 重新分工：A=棋盘世界，B=游戏流程与UI（独立验证版）

> 本文档替代 01/02 中**尚未完成部分**的任务划分。已完成部分不动。
> 设计目标：**双方每个模块都能自己验证，不依赖对方在场联调。** 全程只有 2 个固定联调点。

---

## 一句话边界

- **A：场景里"棋盘"这棵物体树下的一切**——逻辑 + 渲染 + 动画 + 棋盘交互（旋转/拍击输入）。
- **B：棋盘之外的一切**——状态机、关卡/轮次流程、配置表、三选一、Canvas UI、存档、无尽模式。

## 独立验证的三个支柱

1. **依赖单向**：只有 B 依赖 A，A 不依赖 B 的任何东西（HUD 用可空接口，null 也能跑——现状已如此）。
2. **接口先冻结**：A 的核心逻辑已完成且有 40+ 测试兜底，所以 A 的第一个任务就是交付门面接口（预计 1~2 小时，实现都是现成的），签名当场冻结。此后 B 面对的是一个稳定 SDK，出问题先看自己的调用。
3. **B 自带作弊调试工具**（需求文档 P2 本来就要求）：B 测流程不需要真的玩游戏——按键直接加分、瞬间结算、强制轮次结束。B 的全部模块都能在没有"会玩的手"的情况下验证。

## A 的剩余任务（每项都写明独立验证方式）

### A11 门面接口（第一优先，交付即冻结）

新建 `ZZNCBoardController`（`Assets/Scripts/ZZNC/View/`），B 只通过它操作棋盘世界：

| 接口 | B 的调用时机 | 功能 |
|---|---|---|
| `LoadBoard(BoardTemplate, IEnumerable<Hex> walls)` | LevelInit / RoundInit | 清空并重建棋盘与渲染 |
| `SpawnPiece(PieceType, Hex pos)` | 初始生成、三选一 | 摆棋子（含建 View）。位置由 B 从 `EmptyCells()` 随机选好传入（随机数归 B） |
| `AddWall(Hex pos)` | 轮间新增墙体 | 放墙；格上有棋子则静默删除 |
| `RotateBoard(int steps)` / `int BoardOrientation { get; }` | RotationPreview | 旋转表现与朝向维护整体归 A |
| `ExecuteSmack(SmackRules, Action<SmackResult>)` | 拍击确认后 | 不再传 orientation，A 自持朝向 |
| `SetInputEnabled(bool)` | 状态切换时 | 锁定/放开旋转与拍击输入 |
| `event Action OnSmackRequested` | — | 玩家按拍击键时上抛，B 扣次数、切状态后再调 ExecuteSmack |
| `Board` 只读查询（EmptyCells / AllPieces） | 任意非结算状态 | 照旧 |

**独立验证**：把现有 TempPlaytest 改造成门面的第一个消费者——A 自己的 TestScene 里用按键模拟 B 的调用序列（LoadBoard→SpawnPiece×N→旋转→拍击→AddWall→再来），全程不需要 B 的任何代码。

### A12 棋盘模板（6/8/10 三种）

- 数据含：合法格列表、可生成棋子格集合、可生成墙体格集合、MaxRowLength。做成资产或纯代码静态表均可，B 的配置只引用 ID。
- **独立验证**：TestScene 按键切换三个模板，肉眼看形状 + EditMode 测试断言格数和 MaxRowLength。

### A13 真动画

- 替换 0.1s 空实现：移动补间（DOTween）、受击震动、能力特效、生成/移除表现。"返回时长、串行播放"契约不变。
- **独立验证**：TestScene + SmackDebugger 现有 4 个 Case 直接看表现；逻辑测试已兜底，动画只影响观感不影响正确性。

### A14 拍击输入上抛

- 拍击键触发 → 发 `OnSmackRequested`，不直接结算。TestScene 里自己订阅这个事件直接转调 ExecuteSmack 即可验证。

## B 的任务（每项都写明独立验证方式）

### B0 调试作弊面板（第一优先，反直觉但值得）

一个 Debug 面板/快捷键集：**手动加分、手动扣拍击次数、强制轮次结算、强制过关/失败、跳过三选一**。
这是 B 所有后续模块的"独立验证器"——测轮次结算不需要真的打出 500 分，按 F1 加分即可。约半小时投入，节省全程联调。
**独立验证**：自身就是验证工具。

### B1 游戏状态机

- enum + switch。状态切换全部打日志。
- **独立验证**：不接棋盘也能测——先用一个"假结算"（0.5 秒后直接回调随机 SmackResult）把整个状态机闭环跑通：Boot→LevelInit→…→RoundJudge→LevelFail/Success 每条路径用作弊面板逐一走到。**这里用假结算不是为了等 A，而是为了隔离验证状态机本身。**

### B2 配置表（ScriptableObject）

- LevelConfig（轮次数、拍击数、目标分、墙体数、三选一池）、PieceConfig、EventSafetyConfig；打包 `SmackRules` 传 A。
- **独立验证**：EditMode 测试或 OnValidate 断言配置合法性（目标分>0、轮次数匹配等）。

### B3 关卡/轮次流程

- LevelInit 调门面建棋盘摆棋子；RoundJudge 按 `CurrentScore >= TargetScore` 通过（**以需求文档 5.2 为准**，02 文档里"等于也算失败"作废）；失败重开、关卡切换不继承、无尽入口。
- **独立验证**：作弊面板加分/扣次数，遍历"过关继承分数""失败重开""三关后无尽"每条分支，看日志和棋盘重建结果。A 的门面此时已冻结，出问题先查自己传参。

### B4 三选一

- 抽 3 不重复 + 跳过；选中 → EmptyCells 随机 → `SpawnPiece`。棋盘满则丢弃+提示。
- **独立验证**：作弊面板直接触发三选一；用一个 1 格模板（或作弊填满棋盘）验证"棋盘满丢弃"分支。

### B5 轮间墙体

- 从模板"可生成墙体格"随机不重复取 → `AddWall`。
- **独立验证**：作弊面板强制过关触发，反复几次看墙数量、替换棋子是否静默删除。

### B6 UI / HUD

- 常驻 HUD、结算/失败界面、"棋盘已满/能量过载"提示、实现 `IHUDView.ShowScorePop`。
- **独立验证**：作弊面板驱动一切数值变化；ShowScorePop 自己写个按键调用测试飘字，不需要等真实结算触发。

### B7 存档（可裁）

- PlayerPrefs 存最高进度。作弊面板改进度后重启验证。
