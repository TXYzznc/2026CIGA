# 程序A 开发文档：回合内（拍击 → 结算 → 稳定）

> 先读 `00-共同契约-接口与耦合（双方必读）.md`。
> 你的领地：从玩家按下拍击那一刻起，到棋盘稳定回调 `onRoundStable` 为止的一切逻辑与表现。
> 你的代码放 `Assets/Scripts/Core/`。**不打开场景文件、不改 prefab 资产。**
> 规则细节一律以策划案 `raw/六边形重力连锁玩法策划案.md` 为准，本文只列模块与要点。

## 模块清单（按开发顺序）

### A1 六边形坐标系统（第一天上午完成并冻结）

- `Hex(q, r)` 轴坐标、六方向 `D0~D5`（顺时针）、邻格、六边形距离。
- 朝向换算：`boardOrientation (0~5)` → `CurrentGravityDirection`。约定 Orientation=0 时屏幕下方=D0；棋盘顺时针转一档，重力方向在逻辑坐标里逆时针退一档。
- 放 `Shared/`，这是双方地基，写完先让 B 过目一眼再冻结。

### A2 棋盘数据模型（Board / Piece）

- 按契约文档的接口实现。内部用 `Dictionary<Hex, ...>` 即可，不用追求性能。
- Piece.ID 自增分配；墙体是 CellContent，不是 Piece。
- **写一组纯 C# 断言测试**（EditMode 测试或控制台皆可），后面每个规则模块都补测试——这是你 48 小时内最省时间的投资，分裂棋那些刁钻规则靠肉眼调会调死。

### A3 重力轨道与初始事件（策划案 5.2）

- 按当前重力方向把棋盘划分为平行轨道。
- 入队顺序：轨道**屏幕左→右**，轨道内**下→上**（最下方棋子先入队）。
- 注意"屏幕左右"要按当前朝向换算到逻辑坐标，别用固定轴。

### A4 统一事件队列（策划案 5.3 / 7）

- FIFO，新事件只加队尾，永不插队。
- 事件只记：类型、目标棋子ID、方向、来源、上下文。**不提前锁定终点**——执行时按实时棋盘状态重算路径。
- 目标棋子已被移除 → 事件失效跳过。
- **关键架构约束：先算后播**。整个队列先纯逻辑跑完，产出一个有序的"已发生事件记录列表"（每条含起终点、得分等快照），再交给播放器逐条播动画。这样：
  1. 逻辑可以用断言测试；
  2. `SimulateSmack` 预览接口顺手就有了；
  3. 播放中断/加速都不影响正确性。

### A5 事件执行逻辑（九种事件，策划案 7.2 + 伪代码 15）

按策划案伪代码实现，重点边界：

- **GravityMove**：移动到最远合法位置；没有实际位移则不产生碰撞；普通重力不出棋盘。
- **Collision**：仅"移动方向正前方"的相邻棋子；只触发**被撞方**的能力；撞普通棋无事件。
- **AbilityTrigger**：先查 `TriggerCountThisSmack >= PieceTriggerLimit`，再 `+1`、连击 `+1`，然后分发。
- **PushMove（爆炸推动）**：只推 1 格；目标格被占则推动失败不移动；推出棋盘 = 移除且不触发能力、不加连击。
- **Spawn**：直接生成不算位移、不产生碰撞。
- **Remove**：不加连击、不触发能力。

### A6 棋子能力（按顺序实现，每个都先过测试再接下一个）

1. **得分棋**：连击+1 后 `AddScore(基础分 × 当前连击数)`。同一拍击可多次触发。
2. **爆炸棋**：以当前重力方向为第 1 方向，**顺时针**处理六个邻格，每格独立生成 PushMove 事件按序入队。空格/墙不产生事件。
3. **分裂棋**（最难，约占全部规则量 1/4，也是官方裁剪点）：
   - 记录碰撞方向 D → 入队 Remove(自己) → 入队两个 Spawn（先 D 顺时针60°，后逆时针60°），两个 Spawn 互相独立、第一个的结果影响第二个的判定。
   - 生成位被占 → 沿生成方向推整条链（从最远端开始逐个推 1 格，每个实际移动的棋子都做碰撞判定）；链末端是墙/边缘/无空格 → 推动失败。
   - 推动失败 → 最近空格规则：六边形距离最近；距离相同按"从原生成方向起顺时针"排序，再相同按坐标顺序；找到则直接生成（不碰撞），全场无空格则本侧生成失败，**不影响另一侧**。
   - 分裂挤压**不能**把棋子推出棋盘（区别于爆炸）。

### A7 连击与得分（策划案 9）

- 拍击开始时连击清零；结算结束清空，不跨回合。
- 连击按**能力执行次数**计，不按影响棋子数。
- 空爆炸（周围没得推）、双侧生成都失败的分裂 → **仍算**有效触发、仍加连击。
- 单次拍击总得分累加进 `SmackResult.ScoreGained`，**累计分数是 B 的事，你不持有**。

### A8 安全上限（策划案 16）

- 单拍击 ≥500 事件 或 单棋子 ≥50 次触发 → 停止生成新事件、清空队列、保留棋盘和已得分数、`SmackResult.EventOverflow = true`、Debug.LogError 记录。

### A9 播放器（回合内表现）

- 拿 A4 产出的事件记录列表，逐条调 `PieceView` 的动画接口（`MoveTo` / `PlayHitShake` / `PlayAbilityFX` / `PlaySpawn` / `PlayRemove`），用返回的时长串时序（协程 await 即可）。
- **严格串行**：策划案 17.2 禁止多个能力视觉上同时执行。移动 → 震动 → 高亮 → 能力 → 连击数字，一步步来。
- 世界坐标通过 B 的 `BoardView.HexToWorld()` 取，别自己算。
- Spawn/Remove 时调 `IPieceViewFactory`。
- 全部播完 → 调 `onRoundStable(result)`，恰好一次。
- 初期 B 给的是空实现动画（0.1s），照常开发，别等表现。

### A10 预览接口 `SimulateSmack`（最后做，可裁剪）

- 只模拟初始重力移动一步（不模拟连锁），复用 A3+A5 的移动计算，跑在棋盘副本上，无副作用。
