## 模块清单（按开发顺序）

### B1 游戏状态机（全局主干，最先搭）

照策划案 14 实现：

```text
LevelInit → RotationPreview → ResolvingEvents → RoundStable
                                                  ├→ PieceChoice → RotationPreview
                                                  └→ LevelJudge → LevelSuccess / LevelFail
```

- 一个简单 enum + switch 就够，不需要状态机框架。
- 各状态操作权限严格按策划案表格：只有 `RotationPreview` 能旋转和拍击，只有 `PieceChoice` 能选棋子。
- **`ResolvingEvents` 期间锁死一切输入且不碰 Board**（读写互斥契约）。
- 开发前 12 小时用一个假的 `ExecuteSmack`（打印日志+直接回调）把整个状态机闭环先跑通。

### B2 棋盘渲染与生成（BoardView）

- 六边形格子、棋子、墙体的 prefab；`Hex → Vector3` 世界坐标换算（**这个函数 A 要用，尽早给**，注意要考虑棋盘当前旋转角度）。
- 尖顶/平顶六边形二选一后和 A 确认方向定义一致（画一张 6 方向对照图贴群里）。
- `PieceView`（MonoBehaviour）：第 1 小时先给全空实现（每个动画函数返回 0.1f），让 A 先跑；真动画后补——移动补间、受击震动、能力特效、生成/移除表现。
- `IPieceViewFactory` 实现：按 PieceType 实例化对应 prefab。
- 四种棋子的视觉区分度是策划案 17.4 的硬要求：普通=低饱和、得分=金色/发光、爆炸=放射/危险色、分裂=双核心。Jam 里纯色+图标就够。

### B3 关卡流程（策划案 11）

- **初始化**：读配置 → `Board.Clear()` → 建棋盘 → `PlaceWall` 摆墙 → 按权重随机生成初始棋子（`PlacePiece`，记得先用工厂建 View）→ 分数=0、拍击次数=配置值 → 进 RotationPreview。初始棋子允许相邻，不触发碰撞。
- **结算**：`当前累计分数 - 目标分数 > 0` 过关（**等于也算失败**，注意 UI 文案要写清"高于"）。
- 成功 → 下一关全部重建，不继承；失败 → 当前关重新初始化。
- 随机数都在你这边；给 Random 一个可打日志的种子，方便复现 bug。

### B4 旋转交互

- 输入方式自定（按钮/拖拽/键盘均可，Jam 建议先做两个按钮：顺时针60°、逆时针60°）。
- 维护 `BoardOrientation (0~5)`，旋转动画只转表现层（BoardView 的根节点），**逻辑坐标不变**——旋转过程中棋子不移动是核心规则。
- 屏幕下方常驻重力箭头。
- 拍击按钮：按下 → 切 `ResolvingEvents` → 调 `ExecuteSmack(BoardOrientation, rules, OnRoundStable)`。

### B5 拍击收尾（OnRoundStable 回调）

```csharp
void OnRoundStable(SmackResult r) {
    totalScore += r.ScoreGained;
    if (r.EventOverflow) 播放"能量过载"提示;
    remainingSmacks -= 1;          // 或在拍击按下时扣，二选一定死
    if (remainingSmacks > 0) → PieceChoice;
    else                    → LevelJudge;
}
```

**分数归属**：累计分数、目标分判定归你；连击和单次得分归 A。别在你这边重复算连击。

### B6 三选一系统（策划案 10）

- 从当前关棋子池按权重抽 3 个**不重复**选项；玩家选 1 或跳过。
- 选中后：`Board.EmptyCells()` 等概率随机取一格 → 工厂建 View → `PlacePiece`。生成不受重力、不碰撞、不触发能力。
- 棋盘满：直接丢弃，提示"棋盘已满，无法放置"，正常进下一回合。
- 权重/必出/保底是裁剪项，首版纯随机即可。

### B7 UI / HUD

- 常驻：剩余拍击数、当前分 / 目标分、拍击按钮、重力箭头。
- 结算界面：累计分、目标分、超出分、下一关/重开按钮。
- 回合内飘分和连击数字的**触发时机由 A 的播放器驱动**——最简单的做法：把飘分做进 `PieceView.PlayAbilityFX()` 或给 A 一个 `HUD.ShowScorePop(int score, int combo, Vector3 worldPos)` 接口（加进契约再用）。
- "棋盘已满""能量过载"两条提示。

### B8 配置表（ScriptableObject）

- 关卡配置：棋盘尺寸/形状、墙体布局、初始棋子数量与权重、三选一池与权重、拍击次数、目标分数、EventLimit、PieceTriggerLimit。
- 棋子配置：类型、基础分、各权重。
- 传给 A 时打包成 `SmackRules` 精简结构（见契约）。
- 首版做 3~5 关手摆数据即可，按策划案 12 的解锁节奏：教学1（普通+得分）→ 教学2（+爆炸）→ 教学3（+分裂）→ 组合关。

### B9 旋转预览（最后做，第一裁剪项）

- 调 A 的 `SimulateSmack(BoardOrientation)`，画落点虚影 + 碰撞棋子描边。
- 每次旋转结束后调一次（不要每帧调）。
- 砍掉时只保留重力箭头，游戏照样成立。

## 纪律提醒

- `ResolvingEvents` 期间你只读不写 Board——三选一、初始化等一切写操作都发生在其他状态。
- 场景是你的，但**别把 A 的测试脚本挂进主场景**；给他单独留一个 `TestScene` 他自己折腾。
- 每 2~3 小时 push；改 `Shared/` 先喊 A。
- 你的模块多而浅，警惕"每个都做到 80 分"：先全部串成闭环（状态机+假结算），再逐个补内容。**36h 后只修 bug 不加功能。**
