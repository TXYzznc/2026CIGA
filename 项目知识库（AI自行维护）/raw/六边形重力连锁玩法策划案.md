# 六边形重力连锁玩法策划案

## 一、玩法概述

### 1.1 玩法定位

本玩法是一款以“旋转棋盘改变重力路径”为核心操作，以“碰撞触发棋子能力、制造连锁反应”为核心策略的六边形棋盘解谜游戏。

玩家不能直接移动棋子，而是通过调整棋盘朝向，并使用有限次数的“拍击”，让棋盘内的棋子按照屏幕下方的重力方向移动。棋子移动后可能发生碰撞，进而触发爆炸、分裂、得分等能力。

玩家需要在有限拍击次数内规划棋盘方向，利用棋子的空间关系制造尽可能长的能力连锁，获得高于关卡要求的分数。

### 1.2 核心体验

核心体验由以下四部分组成：

1. **旋转规划**：观察旋转后各棋子的重力路径。
2. **拍击验证**：确认方向后拍击棋盘，执行重力移动。
3. **连锁结算**：碰撞触发能力，能力继续推动、分裂或撞击其他棋子。
4. **局面构筑**：每回合结算后进行三选一，向棋盘内补充棋子，为后续连锁创造条件。

### 1.3 核心循环

```text
进入关卡
→ 生成棋盘、墙体和初始棋子
→ 玩家自由旋转预览
→ 玩家按下拍击
→ 消耗1次拍击次数
→ 执行重力移动
→ 处理碰撞与能力连锁
→ 棋盘稳定
→ 若仍有拍击次数，进行棋子三选一
→ 进入下一回合
→ 拍击次数耗尽
→ 结算关卡分数
→ 成功进入下一关 / 失败重开当前关
```

## 二、基础概念定义

### 2.1 关卡

一关包含若干个回合。

每关独立配置：

- 棋盘尺寸；
- 棋盘形状；
- 墙体位置；
- 初始棋子数量；
- 初始棋子类型权重；
- 可选择棋子池；
- 各棋子抽取权重；
- 拍击次数；
- 目标分数；
- 事件执行安全上限。

### 2.2 回合

一次完整回合由以下流程组成：

```text
旋转预览
→ 拍击确认
→ 重力移动
→ 事件队列结算
→ 棋盘稳定
→ 三选一
```

一次拍击即为一个回合。

回合之间继承：

- 当前棋盘；
- 当前墙体；
- 当前棋子；
- 当前累计分数。

关卡之间不继承以上内容。

### 2.3 拍击次数

玩家每按下一次拍击按钮，消耗1次拍击次数。

拍击次数消耗与玩家旋转的角度无关：

- 旋转60°后拍击：消耗1次；
- 旋转120°后拍击：消耗1次；
- 旋转180°后拍击：消耗1次；
- 保持当前方向直接拍击：消耗1次。

在按下拍击前，玩家可以任意调整棋盘方向，不消耗拍击次数。

### 2.4 重力方向

重力永远朝向屏幕下方。

玩家旋转的是棋盘，而不是重力方向。

棋盘共有六种合法朝向，相邻朝向相差60°。玩家可以顺时针或逆时针旋转，并可直接调整60°、120°或180°。

旋转过程中棋子不会移动。

只有玩家按下拍击后，棋子才会受到重力影响。

---

## 三、棋盘规则

### 3.1 棋盘结构

棋盘由六边形格组成，每个格子只能容纳以下一种对象：

- 空格；
- 普通棋子；
- 特殊棋子；
- 墙体。

所有棋子均占据1格。

随着关卡推进，棋盘尺寸可以逐步扩大。

### 3.2 棋盘坐标

程序建议使用六边形轴坐标：

```text
(q, r)
```

六个相邻方向统一定义为：

```text
D0、D1、D2、D3、D4、D5
```

六个方向按照顺时针顺序排列。

棋盘旋转后，需要根据当前棋盘朝向，将“屏幕下方”映射为六个方向中的一个，记为：

```text
CurrentGravityDirection
```

### 3.3 墙体

墙体占据1个六边形格。

墙体具有以下性质：

- 跟随棋盘一起旋转；
- 不受重力影响；
- 不受爆炸推动；
- 不受分裂挤压；
- 不会被生成；
- 不会被销毁；
- 不参与三选一；
- 不具有能力；
- 不产生连击；
- 不属于棋子。

墙体布局由关卡配置决定，默认固定，不在关卡内随机变化。

---

## 四、旋转与拍击规则

### 4.1 旋转阶段

在旋转阶段，玩家可以：

- 顺时针旋转；
- 逆时针旋转；
- 旋转60°；
- 旋转120°；
- 旋转180°；
- 将棋盘转回原方向；
- 保持当前方向。

旋转阶段不消耗次数。

建议在旋转预览时显示：

- 当前重力方向；
- 每个棋子的预计移动轨迹；
- 可能发生碰撞的棋子；
- 棋子最终落点。

预计轨迹仅作为辅助表现，最终结果以事件队列实时结算为准。

### 4.2 拍击阶段

玩家按下拍击后：

1. 锁定当前棋盘方向；
2. 禁止继续旋转；
3. 禁止再次拍击；
4. 消耗1次拍击次数；
5. 本回合连击数重置为0；
6. 根据当前棋盘状态生成初始重力移动事件；
7. 进入结算阶段。

结算完全结束前，玩家不能进行任何棋盘操作。

拍击不可撤销。

---

## 五、重力移动规则

### 5.1 基础移动

棋子受到重力时，会沿当前重力方向移动至最远合法位置。

棋子不会只移动1格，而是持续移动，直到前方出现以下情况之一：

- 其他棋子；
- 墙体；
- 棋盘边缘。

普通重力不会让棋子掉出棋盘。

棋子会停留在棋盘最边缘的合法格子中。

只有爆炸推动可以将棋子推出棋盘。

### 5.2 重力轨道

根据当前重力方向，将棋盘划分为若干条平行的重力轨道。

初始重力移动事件按照以下顺序加入统一事件队列：

1. 轨道按照屏幕位置从左到右排序；
2. 每条轨道内部按照重力方向从下到上排序；
3. 最下方棋子的移动事件先入队；
4. 最上方棋子的移动事件最后入队。

例如同一轨道中存在：

```text
A
B
空
空
棋盘底部
```

执行顺序为：

1. B先移动至棋盘底部；
2. A随后向下移动；
3. A最终停在B前方；
4. A对B产生一次碰撞。

### 5.3 实时状态读取

事件只记录：

- 事件类型；
- 目标棋子ID；
- 移动方向；
- 事件来源；
- 必要的上下文信息。

事件不提前锁定最终位置。

移动事件真正执行时，根据棋子的实时位置和当前棋盘状态重新计算路径。

如果棋子在事件执行前已经被移除，则该事件失效并跳过。

### 5.4 悬空规则

只有拍击会触发全棋盘重力。

爆炸、分裂和其他能力产生的位移不会重新触发全局重力。

如果能力执行后产生悬空棋子，棋子会保持悬空状态，等待下一次拍击。

---

## 六、碰撞规则

### 6.1 碰撞成立条件

棋子A对棋子B产生碰撞，必须同时满足：

1. A在本次事件中实际移动了至少1格；
2. A移动结束后，移动方向正前方的相邻格存在棋子B；
3. B是棋子，而不是墙体。

只有正前方棋子是碰撞目标。

A周围其他方向的相邻棋子不参与本次碰撞。

### 6.2 不产生碰撞的情况

以下情况不产生碰撞：

- A没有发生实际位移；
- A被墙体阻挡；
- A被棋盘边缘阻挡；
- A的前方为空格；
- 棋子通过直接生成出现在其他棋子旁边；
- 棋子被推出棋盘；
- 推动失败，棋子没有移动。

### 6.3 能力触发对象

当A撞击B时：

- 只触发被撞棋子B的能力；
- A的能力不会因为主动撞击而触发；
- A只有在之后成为其他棋子的被撞目标时，才会触发自身能力。

普通棋子被撞击时不产生能力事件。

---

## 七、统一事件队列

### 7.1 队列原则

所有移动、碰撞、能力和生成行为进入同一个事件队列。

队列采用FIFO规则：

```text
先入队，先执行
```

任何事件执行过程中生成的新事件，都加入当前队列尾部。

事件不会插队。

### 7.2 事件类型

首版包含以下事件：

| 事件类型 | 说明 |
|---|---|
| GravityMove | 拍击产生的重力移动 |
| PushMove | 爆炸或分裂产生的推动 |
| Collision | 棋子对正前方棋子产生碰撞 |
| AbilityTrigger | 执行被撞棋子的能力 |
| Explosion | 执行爆炸效果 |
| Split | 执行分裂效果 |
| Spawn | 生成新棋子 |
| Remove | 从棋盘移除棋子 |
| Score | 增加关卡分数 |

### 7.3 基础执行流程

```text
移动事件执行
→ 读取棋子实时状态
→ 计算可移动位置
→ 执行位移
→ 检查正前方对象
→ 若为棋子，加入Collision事件
→ Collision事件执行
→ 根据目标棋子类型加入AbilityTrigger事件
→ AbilityTrigger事件执行
→ 连击数+1
→ 执行具体能力
→ 新事件加入队尾
```

### 7.4 回合稳定条件

同时满足以下条件时，本次拍击结算结束：

1. 统一事件队列为空；
2. 当前没有正在播放的事件动画。

棋盘不要求所有棋子贴底。

即使存在悬空棋子，只要队列为空，本回合仍然结束。

## 八、棋子设计

首版包含四种棋子：

1. 普通棋子；
2. 得分棋；
3. 爆炸棋；
4. 分裂棋。

### 8.1 普通棋子

#### 能力

无特殊能力。

#### 作用

- 作为撞击来源；
- 阻挡其他棋子；
- 改变棋盘空间结构；
- 参与爆炸推动；
- 参与分裂挤压；
- 作为制造连锁的中间单位。

普通棋子被撞击时：

- 不增加连击；
- 不生成能力事件；
- 保留在棋盘中。

### 8.2 得分棋

#### 触发条件

得分棋被其他棋子合法撞击。

#### 执行规则

1. 生成得分棋的能力触发事件；
2. 能力事件执行时，当前连击数+1；
3. 根据更新后的连击数计算得分；
4. 得分棋保留在原位置。

#### 得分公式

```text
本次得分 = 得分棋基础分 × 当前连击数
```

例如基础分为100：

```text
当前连击数为2
→ 得分棋能力触发
→ 连击数变为3
→ 获得300分
```

得分棋可以在同一次拍击中被多次触发。

同一棋子不存在单回合触发次数限制，但受到程序安全上限限制。

得分棋基础分由棋子配置表控制，首版数值待测试后确定。

### 8.3 爆炸棋

#### 触发条件

爆炸棋被其他棋子合法撞击。

#### 执行规则

1. 爆炸能力事件执行；
2. 当前连击数+1；
3. 爆炸棋保留在原位置；
4. 检查爆炸棋六个相邻方向；
5. 对相邻棋子产生向外推动1格的效果。

#### 方向处理顺序

以当前重力方向为第一个方向，按照顺时针顺序处理六个相邻格。

```text
当前重力方向
→ 顺时针第2方向
→ 顺时针第3方向
→ 顺时针第4方向
→ 顺时针第5方向
→ 顺时针第6方向
```

每个方向独立生成推动事件，并按照上述顺序加入队列。

#### 推动规则

只影响紧邻爆炸棋的棋子。

相邻格为空：

- 不产生事件。

相邻格为墙：

- 不产生事件。

相邻格存在棋子：

- 尝试将该棋子沿远离爆炸中心的方向移动1格。

目标格为空：

- 棋子移动1格；
- 移动后检查正前方是否存在棋子；
- 若存在，则产生碰撞。

目标格存在棋子或墙体：

- 推动失败；
- 棋子不移动；
- 不产生碰撞。

目标位置在棋盘外：

- 棋子被推出棋盘并移除；
- 不产生碰撞；
- 不触发被推出棋子的能力；
- 不增加连击。

爆炸推动可以产生新的碰撞和能力连锁。

### 8.4 分裂棋

#### 触发条件

分裂棋被其他棋子合法撞击。

#### 执行规则

1. 分裂能力事件执行；
2. 当前连击数+1；
3. 记录本次碰撞方向；
4. 将原分裂棋的Remove事件加入队列；
5. 将两个Spawn事件依次加入队列；
6. 原分裂棋被移除；
7. 在撞击方向两侧各生成一个新的分裂棋。

#### 分裂方向

设碰撞方向为D。

两个生成方向分别为：

- D顺时针偏转60°；
- D逆时针偏转60°。

先处理顺时针偏转方向，再处理逆时针偏转方向。

两个生成事件互相独立。

第一枚棋子的生成结果会改变棋盘状态，并影响第二枚棋子的生成判定。

#### 原棋子移除

原分裂棋的消失属于一次Remove事件。

该移除事件：

- 不额外增加连击；
- 不再次触发分裂能力；
- 不触发其他能力；
- 可以作为未来“离场时触发”系统的扩展接口。

#### 新棋子类型

分裂生成的新棋子仍然是分裂棋。

生成后的分裂棋可以再次被撞击并继续分裂。

#### 生成位置为空

如果目标格合法且为空：

- 直接生成分裂棋；
- 生成不属于位移；
- 不产生碰撞；
- 不触发周围棋子；
- 等待后续事件或下一次拍击。

#### 生成位置被占用

优先尝试沿生成方向推动整条棋子链。

例如：

```text
生成位置 → A → B → 空格
```

执行结果：

```text
新分裂棋 → A → B
```

推动规则：

1. 从棋子链最远端开始处理；
2. 最远棋子先移动；
3. 依次向靠近生成位置的方向执行；
4. 每个棋子向生成方向移动1格；
5. 最终在原目标格生成新的分裂棋；
6. 所有实际移动的棋子均进行碰撞判定；
7. 移动结束后，若其正前方存在棋子，则产生碰撞事件。

分裂挤压不能将棋子推出棋盘。

如果棋子链末端为以下情况，则推动失败：

- 墙体；
- 棋盘边缘；
- 没有可用空格。

#### 推动失败后的最近空格规则

推动失败后，寻找棋盘内距离分裂原位置最近的合法空格。

合法空格必须满足：

- 位于棋盘内；
- 不是墙体；
- 没有棋子。

距离使用六边形格距离计算。

如果存在多个距离相同的空格：

1. 从原生成方向开始；
2. 按照顺时针方向排序；
3. 若角度仍相同，再按棋盘坐标顺序决定；
4. 选择第一个合法空格。

找到空格后直接生成分裂棋。

该生成不产生碰撞。

如果棋盘内没有任何空格，则本次生成失败。

一侧生成失败不会影响另一侧生成。

## 九、连击与得分系统

### 9.1 连击重置

每次拍击开始时：

```text
当前连击数 = 0
```

本次拍击结算结束后，连击数清空。

连击不会继承到下一回合。

### 9.2 有效能力触发

以下事件执行时，连击数+1：

- 得分棋能力成功执行；
- 爆炸棋能力成功执行；
- 分裂棋能力成功执行。

连击按照能力执行次数计算，而不是按照能力影响的棋子数量计算。

例如：

- 爆炸影响5个棋子，仍只增加1次连击；
- 分裂成功生成2个棋子，仍只增加1次连击；
- 得分棋被撞击2次，分别增加2次连击。

### 9.3 仍算有效触发的情况

以下能力即使没有产生实际空间效果，仍算有效能力触发：

- 爆炸棋触发，但周围没有可推动棋子；
- 分裂棋触发，但两个新棋子都生成失败。

原因是棋子的能力事件已经被成功执行。

### 9.4 不增加连击的情况

- 普通棋子被撞；
- 棋子撞墙；
- 棋子撞棋盘边缘；
- 推动失败；
- 棋子被推出棋盘；
- 直接生成棋子；
- 因对象已被移除而失效的事件；
- Remove事件。

## 十、三选一系统

### 10.1 出现时机

一次拍击完成全部事件结算后：

- 如果仍有剩余拍击次数，进入三选一阶段；
- 如果拍击次数已经耗尽，直接进入关卡结算，不出现三选一。

### 10.2 选项生成

系统从当前关卡的棋子池中抽取三个不同的棋子选项。

同一次三选一中不允许重复。

不同回合之间可以重复出现相同棋子。

抽取受到以下配置影响：

- 棋子是否已解锁；
- 当前关卡是否允许出现；
- 棋子抽取权重；
- 必出规则；
- 保底规则。

### 10.3 玩家选择

玩家可以：

- 选择三个棋子中的一个；
- 跳过本次选择。

玩家选择棋子后，系统从全部合法空格中等概率随机选择一个位置。

合法位置：

- 位于棋盘内；
- 不是墙体；
- 当前没有棋子。

新棋子生成后：

- 不立即受到重力；
- 不产生碰撞；
- 不触发能力；
- 等待下一次拍击。

### 10.4 棋盘已满

如果玩家选择棋子时棋盘内不存在合法空格：

- 本次棋子直接丢弃；
- 不替换已有棋子；
- 不获得分数补偿；
- 正常进入下一回合。

界面提示：

```text
棋盘已满，无法放置
```

## 十一、关卡流程与结算

### 11.1 关卡初始化

进入关卡时：

1. 读取关卡配置；
2. 创建对应尺寸棋盘；
3. 放置固定墙体；
4. 根据初始棋子数量和权重随机生成棋子；
5. 初始棋子允许彼此相邻；
6. 相邻不会直接触发碰撞；
7. 当前分数设为0；
8. 当前拍击次数设为关卡配置值；
9. 进入旋转阶段。

### 11.2 回合继承

同一关卡的回合之间继承：

- 棋盘；
- 墙体；
- 所有存活棋子；
- 棋子位置；
- 当前累计分数；
- 当前剩余拍击次数。

### 11.3 关卡结算

拍击次数耗尽，并且最后一次事件队列完全结算后，计算：

```text
结算差值 = 当前累计分数 - 本关目标分数
```

判定规则：

```text
结算差值 > 0：过关
结算差值 <= 0：失败
```

因此，分数刚好等于目标分数时，仍然判定失败。

#### 成功

- 展示本关累计分数；
- 展示目标分数；
- 展示超出分数；
- 进入下一关；
- 下一关重新创建棋盘；
- 下一关重新生成棋子；
- 下一关分数重置为0；
- 不继承上一关棋盘、棋子和剩余分数。

#### 失败

- 不保存负分；
- 不保留失败时棋盘；
- 重新初始化当前关卡；
- 分数重新设为0；
- 拍击次数恢复；
- 棋盘和棋子按照当前关卡配置重新生成。

## 十五、程序伪代码

```text
OnSmack():
    if State != RotationPreview:
        return

    State = ResolvingEvents
    RemainingSmackCount -= 1
    CurrentCombo = 0

    tracks = BuildGravityTracks(CurrentGravityDirection)
    tracks.Sort(LeftToRight)

    for track in tracks:
        pieces = track.GetPieces()
        pieces.Sort(BottomToTop)

        for piece in pieces:
            EventQueue.Enqueue(
                GravityMoveEvent(piece.ID, CurrentGravityDirection)
            )

    ProcessEventQueue()
```

```text
ProcessEventQueue():
    while EventQueue is not empty:
        if TotalExecutedEventCount >= EventLimit:
            EventQueue.Clear()
            LogEventOverflow()
            break

        event = EventQueue.Dequeue()

        if event.TargetInvalid():
            continue

        Execute(event)
        PlayEventAnimation(event)
        TotalExecutedEventCount += 1

    WaitUntilAllEventAnimationsFinished()
    OnRoundStable()
```

```text
ExecuteMoveEvent(piece, direction):
    if piece does not exist:
        return

    startPosition = piece.Position
    targetPosition = CalculateFarthestLegalPosition(
        piece.Position,
        direction
    )

    if targetPosition == startPosition:
        return

    MovePiece(piece, targetPosition)

    frontCell = GetNeighbor(targetPosition, direction)

    if frontCell contains Piece:
        EventQueue.Enqueue(
            CollisionEvent(piece.ID, frontCell.Piece.ID, direction)
        )
```

```text
ExecuteCollisionEvent(source, target, direction):
    if source or target does not exist:
        return

    if target.PieceType == Normal:
        return

    EventQueue.Enqueue(
        AbilityTriggerEvent(target.ID, direction, source.ID)
    )
```

```text
ExecuteAbilityTrigger(target, collisionDirection):
    if target does not exist:
        return

    if target.TriggerCountThisSmack >= PieceTriggerLimit:
        return

    target.TriggerCountThisSmack += 1
    CurrentCombo += 1

    switch target.PieceType:
        Score:
            AddScore(target.BaseScore * CurrentCombo)

        Explosion:
            EnqueueExplosionEvents(target)

        Split:
            EnqueueSplitEvents(target, collisionDirection)
```

## 十六、异常与死循环保护

由于分裂棋可以继续分裂，爆炸和推动也可能持续产生新碰撞，因此必须设置事件保护。

默认规则：

- 单次拍击最多执行500个事件；
- 单个棋子在一次拍击中最多触发能力50次。

超过任意上限后：

1. 停止生成新事件；
2. 清空剩余事件队列；
3. 结束本次连锁；
4. 保留当前棋盘状态；
5. 保留本次已经获得的分数；
6. 播放“能量过载”表现；
7. 记录完整错误日志；
8. 进入本回合稳定阶段。

该限制属于程序保护，正常关卡设计中不应频繁触发。

## 十七、表现与交互需求

### 17.1 旋转预览

旋转时建议提供：

- 屏幕下方重力箭头；
- 棋盘当前角度；
- 棋子预计下落路径；
- 预计碰撞目标描边；
- 最终落点虚影；
- 拍击按钮高亮。

### 17.2 结算表现

事件必须严格按照队列顺序播放。

禁止多个能力在视觉上完全同时执行，否则玩家无法理解连锁因果。

推荐节奏：

```text
棋子移动
→ 碰撞震动
→ 被撞棋子高亮
→ 能力触发
→ 连击数字提升
→ 新事件继续执行
```

### 17.3 分数表现

得分棋触发时显示：

```text
基础分 × 当前连击数 = 本次得分
```

例如：

```text
100 × 4
+400
```

当前版本可先实现基础得分信息，完整COMBO界面作为后续表现优化内容。

### 17.4 信息可读性

不同棋子必须具有明确视觉语言：

- 普通棋：低饱和、结构简单；
- 得分棋：金币、数字或发光核心；
- 爆炸棋：放射结构、危险色、范围预示；
- 分裂棋：双核心、细胞或裂纹结构；
- 墙体：厚重、静止、不可移动感。

## 十八、首版验证重点

首版原型优先验证以下问题：

1. 玩家能否理解“旋转不移动，拍击才移动”；
2. 六边形方向下的下落路径是否容易预测；
3. FIFO连锁是否具有足够清晰的因果关系；
4. 爆炸推动是否能稳定制造二次碰撞；
5. 分裂棋是否过快填满棋盘；
6. 无限分裂是否容易触发事件安全上限；
7. 三选一随机放置是否会削弱玩家策略感；
8. 普通棋、特殊棋的出现比例是否合理；
9. 得分增长是否过度依赖早期能力触发顺序；
10. “必须高于目标分，等于目标分仍失败”是否会造成玩家理解问题。

## 十九、玩法特色总结

本玩法的核心差异点并不是传统意义上的“旋转后自动下落”，而是将旋转与重力结算拆分为两个阶段：

```text
自由调整棋盘
→ 玩家主动拍击确认
→ 重力与连锁集中爆发
```

这种设计让旋转阶段承担策略预测，拍击阶段承担结果验证。

爆炸、分裂和得分棋则构成三种互相配合的功能：

- 爆炸棋负责改变棋子位置，扩大连锁；
- 分裂棋负责增加棋子数量，改变空间结构；
- 得分棋负责将连锁深度转化为关卡收益；
- 普通棋负责填充、阻挡和传递碰撞。

玩家的长期目标是在每关有限的拍击次数中，通过旋转方向选择和棋子构筑，让能力事件按照有利顺序进入FIFO队列，形成高倍率得分连锁。
